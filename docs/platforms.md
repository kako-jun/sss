# 対応環境

## 対応OS

| OS      | サポート状況                                                                            |
| ------- | --------------------------------------------------------------------------------------- |
| Windows | 対応（CI は windows-latest でビルド・テスト。配布物は portable ZIP）                    |
| Linux   | 対応（CI は Ubuntu 22.04 でビルド・テスト。WebKitGTK 4.1 が必要。AppImage / deb / rpm） |
| macOS   | 対応（CI は macos-latest でビルド・テスト。配布物は universal の `.dmg`）               |

Windows・Linux・macOSのすべてで同じ操作感を提供します。ファイルマネージャーとの連携もOS別に実装されています（Windows: エクスプローラー、macOS: Finder、Linux: nautilus / dolphin / xdg-open）。

配布物（[Releases](https://github.com/kako-jun/sss/releases)）にはコード署名をしていないため、初回起動時に Windows SmartScreen / macOS Gatekeeper の警告が出ます。回避手順は README を参照してください。

## 対応ファイル形式

### 画像

JPEG、PNG、GIF、BMP、WEBP、TIFF に対応しています（拡張子は `.jpg` / `.jpeg` / `.png` / `.gif` / `.bmp` / `.webp` / `.tiff` / `.tif`）。GIF・WebP のアニメーションはそのまま再生されます。TIFF は WebView が直接表示できないため、表示前にバックエンドが PNG / JPEG へ変換してキャッシュします。EXIF情報（撮影日時・GPS座標・向き）を持つファイルは、その情報をオーバーレイの情報セルに表示します。

### 動画

MP4、WebM、OGV、M4V に対応しています（実際に再生できるかは WebView のコーデック対応に依存します）。動画はウィンドウにフィットするよう表示され、再生終了後（設定した最大再生時間に達した場合はその時点）に自動で次のメディアに進みます。音声は既定でオフです。動画ファイルにはEXIF情報（撮影日時・GPS）は表示されず、ファイルとしての基本情報のみ表示されます。AVI、MKV、FLV、WMV等の旧フォーマットは将来のffmpeg同梱で対応予定です（#45）。

## ディスプレイ

4Kディスプレイ（3840×2160）に最適化されています。それ以外の解像度でも動作します。起動時は全画面で、F / F11 でウィンドウモードに切り替えられ、以後は前回のウィンドウ状態を復元します。4Kを超える写真は表示前に4Kサイズへリサイズ（JPEG品質90%、透過を持つ場合はPNG）してキャッシュに保存することで、メモリ使用量を抑制します。キャッシュはサイズ上限（既定2GB）を超えると古いものから自動削除され、生成は単一のワーカースレッドが直列に行うため連打してもスレッド数・メモリは有界です。

## ストレージ

ローカルディスク上のフォルダを対象とします。表示できるのは、スキャン済みのフォルダ・ピック先・キャッシュのフォルダだけです（Tauri の asset scope を、これらのフォルダに対して起動時とスキャン時に動的に許可します。それ以外の場所のファイルは読み込めません）。OSからマウントされたネットワークドライブも動作しますが、ネットワーク速度によっては表示が遅くなる場合があります。SDカード等の外付けドライブ直下（Windowsの`D:\`等）もスキャン対象に選択できますが、OSやユーザープロファイルが入るシステムドライブの直下（通常`C:\`、Unixの`/`）は安全上の理由で選択できません。

## パフォーマンス目標

以下は設計上の**目標値**で、フルアプリでの通し計測は行っていません。バックエンド単体のベンチ（`src-tauri/tests/` の `#[ignore]` テスト）の実測値は `docs/architecture.md` §6(b) を参照してください。

| 操作                       | 目標                      |
| -------------------------- | ------------------------- |
| 初回スキャン（10万枚）     | 30秒以内                  |
| 差分スキャン（変更100枚）  | 3秒以内                   |
| 起動からスライドショー開始 | 5秒以内（差分スキャン時） |
| 写真の切り替え             | 100ms以内                 |
| メモリ使用量               | 500MB以内（通常動作時）   |

## 制約事項

- **原本のファイル操作なし**: アプリから写真・動画の原本を削除・移動・リネームする機能はありません。大切な写真コレクションを誤操作から守るための仕様です（削除できるのは、ピック機能でコピーしたピック先フォルダ内のファイルだけです）
- **マルチインスタンス不可**: 同一PC上で SSS を複数同時起動することはできません
- **フタ閉じ時のスリープ**: スクリーンセーバーとディスプレイスリープは抑制しますが、ノートPCのフタを閉じた際のスリープは抑制しません（電力節約のため）
- **除外ルールの管理**: 除外ルールはアプリ内データベースに保存されます。フォルダごとの個別設定はできません
- **アニメ形式（GIF/WebP）とEXIF回転設定**: アニメーションしうる形式（GIF/WebP）はキャッシュ対象外のため、EXIF の回転タグ付きの WebP は「EXIF回転」設定をオフにしても WebView が回転して表示します。（設定画面のサムネイルは常に向きを焼き込むため、この設定の影響を受けません）
- **Linux の WebView 要件**: WebKitGTK 2.30 以降を想定しています（画像の向きを WebView 既定の `image-orientation: from-image` に任せる設計のため）。
- **隠しディレクトリ配下の表示**: スキャン対象フォルダの中でもドット始まり（`.`）のサブディレクトリは、Tauri の asset scope 実装（`require_literal_leading_dot`）により `convertFileSrc` での表示ができない場合があります（既定の除外ルール `**/.**/` によりドットフォルダは通常スキャン対象外です）

## 将来の対応プラットフォーム

**タブレット・モバイル**（予定）
Android タブレットおよびiPadへの対応を視野に入れています。デジタルフォトフレームとしてタブレットを活用するユースケースに応えます。スワイプで前後移動、タップでオーバーレイ表示など、タッチ操作への対応が必要です。
