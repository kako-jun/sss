# e2e（実ブラウザ, ローカル専用）

vitest + jsdom では再現できない、実ブラウザ固有のタイミング問題を検証するための
実ブラウザ e2e。playwright-core（devDependency、ブラウザ本体は同梱しない）で
システムにインストール済みの Chrome または Edge を headless 起動する（`chrome` を優先し、無ければ `msedge` にフォールバックする。実行ログの `[e2e] msedge を使用` はこのフォールバックで、Chrome が `channel` から見つからない環境では正常）。

対象は `#65レビュー`（1〜2巡目）で見つかったmust不具合:

- **M1**: `AnimatePresence mode="wait"` は前の要素の退場アニメーション(500ms)が
  終わるまで新しい `<video>` を実際にはマウントしない。isPlaying の変化を見る
  React effect は path が変わった瞬間にも発火するが、その時点ではまだ古い/空の
  `videoRef` を見ており、新要素への `play()` が一度も呼ばれず永久停止していた
  （画像→動画・動画→動画の2本目）。
- **M2**: 1件だけのプレイリスト等で同じ path が連続で返ると、`key`/`src` が
  変わらず `<img onLoad>`/`<video onEnded>` が再発火しない（タイマーが
  張られない・動画が永久に止まる）。
- **S8**（2巡目）: 動画→動画の遷移で、退場中のまだDOM上に残っている古い動画に
  対して `play()` を呼び直してしまい、短い動画では再生位置が0に巻き戻って
  `onEnded` が二重発火し1枚飛ばしていた。
- **S9**（2巡目）: 一時停止中・設定画面表示中も `rootUnavailable`/`error` の
  自動再試行が裏で進んでしまっていた。

いずれも jsdom では `<img>`/`<video>` の読み込み・再生が実際には発生しない
（`play()`/`onload` が呼ばれない）ため、vitest の単体テストだけでは検出できず、
実ブラウザでの検証が要る。

## 実行方法

```sh
npm run e2e
```

- リポジトリルートから実行する。他の dev サーバーとポートが衝突する場合は `E2E_PORT=1109 npm run e2e` のようにポートを変える。
- 結果は全シナリオ終了後にまとめて出力される（実行中は `[e2e] 実行中: {name}` の進捗だけ出る）。
  `E2E_ONLY='(#68),fade'` のようにカンマ区切りの部分文字列を指定すると、名前が一致する
  シナリオだけ実行できる（デバッグ用）。
- 内部で `vite`（既定ポート1420、`E2E_PORT` で変更可）を起動し、終了時に必ず kill する。**先に別の
  `npm run dev`/`npm run tauri:dev` が動いていると起動に失敗するので閉じてから
  実行すること**（起動前にポート使用中かを検知し、その場合はvite起動を試みず
  即座に分かりやすいエラーで終了する。vite自体が起動直後に落ちた場合もタイム
  アウトを待たず即座に失敗する）。
- CI には組み込まない（システムに Chrome/Edge のインストールが要るため）。

## 仕組み

- `init.js`: `page.addInitScript()` でブラウザへ注入し、
  `window.__TAURI_INTERNALS__`（Tauri の IPC 層）を薄くモックする。これにより
  Tauri ランタイム無しで `vite dev` 単体から `App.tsx` をそのまま動かせる。
  URLの `#hash` でシナリオを選ぶ（例: `http://localhost:1420/#one`、ポートは `E2E_PORT` で変更した値）。
- `run.js`: vite dev サーバーの起動・システムブラウザの起動・各シナリオの実行・
  終了処理（vite dev サーバーの確実な kill）を行う。可視判定は `element.hidden`
  等のプロパティでなく実ブラウザの `getComputedStyle` で行う（CLAUDE.md絶対
  ルール1）。

## シナリオ一覧

`run.js` の `scenarios` 配列に全 54 シナリオがあります（`npm run e2e` は全件を順に実行します）。`welcome`/`slides`/`thumbs`/`undo` の各 hash は複数のシナリオが共有します。以下の表は hash ごとの代表的な検証内容で、`welcome`/`slides` を使うシナリオは表の下にまとめています。

| hash          | 検証内容                                                                                                                                                                                                                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `i2v_vv`      | 画像→動画→動画と回しても動画が autoplay で再生され続ける（M1の回帰）                                                                                                                                                                                                                                 |
| `one`         | 1件だけのプレイリストで `get_next_image` が表示間隔ごとに呼ばれ続ける（M2の回帰）                                                                                                                                                                                                                    |
| `welcome`     | ディレクトリ未設定時の「ようこそ」画面                                                                                                                                                                                                                                                               |
| `pickfirst`   | ようこそ→設定の「選択」→`select_and_scan`（引数はダイアログのタイトルのみ、パスを渡さない）→スキャン完了で写真が表示され、前回フォルダが入力欄に反映される（#93）                                                                                                                                    |
| `pickcancel`  | ダイアログをキャンセル（`select_and_scan` が `null`）してもエラー表示・スキャン結果・再生開始が起きず、選択ボタンが再び押せる（#93）                                                                                                                                                                 |
| `empty`       | ディレクトリ設定済みだが0件の専用案内（「ようこそ」ではない）                                                                                                                                                                                                                                        |
| `unreach`     | 起動時の前景スキャン失敗→「前回のフォルダを読めません」全画面案内                                                                                                                                                                                                                                    |
| `toast`       | 復元成功後の背景スキャン失敗→写真を隠さない下部トースト                                                                                                                                                                                                                                              |
| `pausevid`    | 一時停止中に動画へ移っても再生されない・再開で再生され終了後は次へ進む（S8/S9関連）                                                                                                                                                                                                                  |
| `root`        | rootUnavailableは一時停止中は自動再試行しない・再開すると再試行して回復する（S4/S9の回帰）                                                                                                                                                                                                           |
| `broken`      | 壊れた画像で実際に`onError`が起き、`undo_display_count`が呼ばれてから次へ進む（問題8の回帰）                                                                                                                                                                                                         |
| `vv`          | 動画→動画の遷移で、退場中の古い動画要素が再生し直されない（S8の回帰、動画のみを連続させる）                                                                                                                                                                                                          |
| `vidset`      | 動画設定（#68）: 設定UIで音声ON/最大再生時間を保存→`<video>.muted`に反映→再読み込みで復元・キーボード（Space）操作                                                                                                                                                                                   |
| `vidcap`      | 動画設定（#68）: 最大再生時間到達で1回だけ次へ進み、退場中の古い動画がミュート+一時停止される                                                                                                                                                                                                        |
| `vidend`      | 動画設定（#68）: 動画が上限より短ければ従来どおり onEnded で1回だけ進む                                                                                                                                                                                                                              |
| `vidblock`    | 動画設定（#68）: 起動時から音声付き再生が自動再生ポリシーで拒否されても、ミュートへ落として再生を始める（起動時経路）                                                                                                                                                                                |
| `vidresume`   | 動画設定（#68）: 起動時は音声付きで再生し、一時停止後の再開で拒否されたらミュートへ落として再生を続ける（再開時経路）                                                                                                                                                                                |
| `fade`        | 新しくマウントされたメディアは約0.5秒かけてフェードインし、不透明度1で突然現れない（フェードインの回帰）                                                                                                                                                                                             |
| `stats`       | 統計タブ（#67）: ヒストグラムのcanvas描画・「均等」バッジ・棒ホバーのツールチップ（computed styleで可視判定）・表ビューの行数                                                                                                                                                                        |
| `statsspread` | 統計タブ（#67）: 偏りのある分布で「差 N回」バッジ・720px幅でチャートがモーダルからはみ出さない                                                                                                                                                                                                       |
| `statszero`   | 統計タブ（#67）: 全件0回（一度も表示していない）でも0回の棒1本・均等バッジ・「0 / 総数」・表1行になる                                                                                                                                                                                                |
| `undo`        | 除外/ピックの取り消し（#78）: 除外直後に「取り消す」が出て、マウスを動かさず idle（操作バーが opacity 0）になっても残り押せる・押すと `undo_exclude` が `removeRule`/`restorePaths` 付きで呼ばれる。ピックの取り消しは `delete_picked_image` でコピーしたファイルだけを消し、放置すれば約6秒で消える |
| `gestures`    | 写真上のマウス操作（#78）: 写真の実クリックで一時停止/再開（ダブルクリックは1回に畳む）・オーバーレイの「次へ」は一時停止状態を変えない・ホイールで前/次（連続イベントは1回に畳む）                                                                                                                  |
| `thumbs`      | ピック/履歴タブ（#67）: 静止画=サムネイル<img>（naturalWidth<=256）・動画=フィルムアイコン+ファイル名・見えている分だけ要求                                                                                                                                                                          |

新しいシナリオを追加する場合は `init.js` の `seqs`/`invoke` の分岐と `run.js` の
`scenarios` 配列の両方に追記する。

`welcome`/`slides` hash を使うシナリオは次のとおりです。

- 多言語（#80・#82）: `locale: 'en-US'` でようこそ画面・ウィンドウ周り（終了ボタンのツールチップ）が英語で出る／設定のタブ行が ja・en とも1行表示で 720px 幅でも横スクロールしない
- 起動時の復元・背景スキャン・設定画面の「スキャン」が引数なしの `restore_playlist`/`rescan_last_directory` で動き、旧 `scan_directory` を呼ばない（#93。`slides` hash）
- 設定モーダルのレイアウト（#66）: タブを切り替えてもタブ行の上端位置が動かない
- 設定タブ行の高さ（#109）: ja/en × 1920x1080・1280x800・800x600・480x800・360x640 × 全 7 タブで `[role="tablist"]` の `getBoundingClientRect().height` が一定（flex-shrink で潰れない）。狭幅（480x800・360x640）では、選択した各タブがクリックだけでタブ行の可視範囲に入る（#109）。`E2E_PORT` 環境変数で vite のポートを変えられる（他の dev サーバーと衝突を避ける）
- 除外サブメニュー（#110）: 「…」メニュー→「除外」の3項目が 1920x1080〜320x568（幅431px以上は親メニューの左、430px以下は項目の真上へ積み重ね）の全サイズで viewport 内に収まり、操作バー・右上ボタン群と交差せず、親メニュー枠に食い込まず、縦スクロールも不要

#66（ESC/Space/F/?・idleでのカーソル非表示・a11y）向けに以下も追加済み: Escapeが
設定モーダルを閉じるだけでexit_appを呼ばない/何も開いていない時はexit_appを呼ぶ、
Spaceでの一時停止アイコン切替、Fでのフルスクリーン切替IPC呼び出し、`?`でのショート
カット一覧開閉、idle時のカーソル非表示+右上ボタン列のフェード、設定モーダルの
role=dialog/aria-modal・タブのrole=tab/aria-selected、フォーカストラップ、
除外ルール解除ボタンのhoverなし可視性。

## スクリーンショット（before/after比較、`e2e/screenshots.js`）

UI刷新（#66）の前後を同条件で見比べるための撮影スクリプト。仕組みは本ファイル同様
（vite dev + playwright-core + `init.js`のTauri IPCモック）だが、別ポート(1421)で
起動するため `npm run e2e` と同時に実行しても衝突しない。

```sh
node e2e/screenshots.js <出力先ディレクトリ>
```

主要画面（ようこそ・スライド+オーバーレイの操作中/idle・各種案内/トースト・設定の
全7タブ・ショートカット一覧）を ja/en × 幅1280/720 で撮影する。刷新前のスクショを
撮る時は、このスクリプト自体は新規追加ファイルなので `git stash`（追跡済みの
ソース変更だけを退避、未追跡の`screenshots.js`自体は残る）で刷新前のコードに戻して
から実行し、`git stash pop`で復元する。新しい画面（ショートカット一覧等）は刷新前の
コードに存在しないため、見つからない場合は警告を出してスキップし他の撮影を続ける。
